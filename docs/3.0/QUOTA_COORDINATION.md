# 五小时额度协作规程

本规程适用于本项目的 M0 总控与 M1–M8 八个 Codex 窗口。各窗口共用同一账户的 Work/Codex 使用额度；模块窗口不负责估算或监视额度，停工与恢复由 M0 统一下令。

## 额度观测

- M0 从 ChatGPT 桌面端 **设置 → 使用情况 → 概览** 读取“五小时限额”的剩余百分比和重置时间。活动中的 Codex CLI 也可用 `/status` 查看状态。
- 只记录明确显示的五小时剩余额度；不得把周额度、累计使用量或已过去的时间当成五小时剩余额度。
- 不可读取、页面未加载、显示含糊或状态过期时，按 `UNKNOWN` 处理并保持暂停；不得猜测。
- 当前无额度 API 或平台周期自动化。本次协调运行中 M0 保持会话内监看脚本，每 60 秒从 Usage 页面读取一次，并在检查点和推送批次前复核；若脚本退出、页面不可读或状态不明，立即暂停。脚本停止后不再有后台持续监控。

## 停止与恢复

1. 显示剩余额度低于 5% 时，M0 立即广播 `M0-PAUSE`。若页面只显示整数 `5%` 且无法确定是否已低于阈值，则先暂停，直到读数明确。
2. 收到 `M0-PAUSE` 后，各窗口停止开始新的代码修改、测试、浏览器或 GitHub 操作；尽快停在安全检查点，保留工作树、日志与证据，不清理、不回退、不自行提交或推送，并简短回报检查点后等待。
3. 若因真实额度低于 5% 或读数恰为 5% 而暂停，M0 只有在 Usage 明确确认五小时窗口已重置后才广播 `M0-RESUME`；仅凭等待时间不能恢复。若暂停原因仅是读数暂时未知，随后同一窗口出现明确高于 5% 的新读数，则解除该次未知暂停；这不适用于已确认的低额度暂停。M0-RESUME 只唤醒消息中点名的模块。
4. 每次恢复后先完成一个有界工作步骤并回报检查点；M0 复核额度后再分派后续步骤。任何窗口都不得自行解除暂停。

## 并行与推送

- 同时最多运行 2 个开发任务。M0-RESUME 不会自动唤醒已完成或空闲的模块。
- VMware、真实模型和安装测试互斥排程；没有 M0 排程消息不得并行启动。
- GitHub 推送按至少 20 分钟间隔合批；配额暂停期间不推送。PR、CI、测试事实照实记录，不得删除失败测试、降低安全策略或伪造结果。

## 当前授权边界

额度读取只用于协调本账户的这 9 个窗口，不授权购买额度、消费重置额度、升级套餐或修改账户设置。模块只能依据 M0 的 `M0-PAUSE` / `M0-RESUME` 消息和共享控制记录执行。
