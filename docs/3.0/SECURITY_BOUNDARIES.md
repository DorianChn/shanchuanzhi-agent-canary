# 3.0 安全边界

工程候选版，非稳定发布。所有基础防护保持 MIT 开源。

## 受信任主体

宿主程序负责构造 Gateway、Guard、固定工具、资源清单与任务授权。`agent.dispatch` 是唯一向模型提供的调用面。`operator` 对象的持有权是宿主能力，不能序列化或注册成模型工具；它不是远程用户认证协议。现有本地控制台远程审批继续使用原有操作员能力和 CSRF。

文件注册必须在宿主控制的目录中进行。已有文件以句柄持有，注册前后比较 inode / device，拒绝符号链接、不同 realpath、硬链接及超限文件。每次操作检查路径仍绑定原文件，实际读写使用 fd 而不是重新打开模型提供的路径。没有任意路径创建或递归删除接口。

这缩小了路径替换攻击面，但 **不是 OS 沙箱**。有宿主同等权限的本地进程仍能修改文件内容、删除目录、杀死进程或修改日志。Windows 权限由宿主目录 ACL 决定，不能把 POSIX mode 0600 当作 Windows ACL 验证。

## 执行范围

| 功能 | 覆盖 | 限制 |
| --- | --- | --- |
| 文件 | 宿主预登记且持有的现有文件 | 不支持任意目录 / 新文件 / 原子目录事务；错误后不能承诺回滚已开始的写入 |
| 命令 | 宿主固定 executable + argv，无 shell | 固定程序自身的权限由宿主审核；不拦截子进程内部系统调用，不保证终止全部后代进程 |
| 网络 | 宿主批准 HTTPS origin 的只读 GET、DNS 校验并 socket pin、无重定向 | 可信 origin 不能被任意模型修改；GET 路径也可能在服务端有副作用，宿主仍需审核目标 |
| MCP | 明确登记的宿主回调 | 第三方回调语义由宿主负责；既有全局工具不自动覆盖 |
| AI | 模糊风险事前分析，可从待审批收紧为拒绝 | benign、超时、错误仍待人工批准；模型没有管理工具、最终授权权力 |
| Guard | 最终执行前重查；文件操作同一 JS turn 使用句柄 | 不撤销已开始的外部操作；未接入 Gateway / Router 的调用 OUT_OF_SCOPE |
| 证据 | 可信进程记录决定与执行结果、局部哈希链 | 管理员可重写整条链；无独立时间戳、签名、可信外部锚；进程崩溃可能只留 RUNNING |
| 蜜罐 | 新建临时目录中的无效凭据、虚拟 DB / API / MCP | 不挂载用户真实文件；自适应选择是启发式，收益未测 |

审计不可用或容量不足时，执行前拒绝。若执行后的审计失败，隔离会话并报告错误，不能把它描述为副作用已撤销。并发队列最大 64、审批最大 64、证据最大 4096，达到上限需要可信宿主轮转到新记录器 / 会话，不静默丢日志。

## 数据流边界

仅在可观察工具输入输出范围追踪。会话 HMAC 标签和 16 字符片段指纹支持部分常见 base64 / URI 编码和长片段拆分。短片段、任意变换、模型内部记忆、未观测工具不保证识别。当前网关对出现敏感来源后的网络请求使用保守会话拒绝，可能影响无关合法请求；不是完整动态污点分析。

原生 Codex / Claude Code / Cursor / Cline 全局保护未通过端到端验收。本轮真实验证对象明确为受控 SDK Agent。
